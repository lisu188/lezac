# Original Ammunition HUD And Drawing Callees

`FrameHudOperation` now accepts the complete near Pascal ammunition HUD entry
`326E..3355`. Its actual rectangle clear `07C5..07F7` and indexed sprite painter
`12DB..136B` are implemented by `FrameDrawingOperation` on the caller's bus.
The existing `313D` number conversion and `1156` opaque glyph blitter remain
real callees. Each operation retains resumable registers, stack writes, REP
grants, DF behavior and the CRT stack check at `0920:04DF`, including handoff
to runtime error `E2`.

## Recovered Behavior

- The player argument selects the current weapon, ammunition and dirty bytes.
  Dirty values zero and one skip the icon; the callee still clears the dirty
  byte and paints the clamped two-digit count. The live waiting-loop caller
  does not invoke the callee when its dirty byte is zero.
- Icon repaint clears a 16x16 well to palette index 18 and writes the same
  value to shared byte `DS:79A3`. Descriptor centering uses unsigned `SHR`,
  including dimensions greater than 16. The descriptor lookup retains the
  full selected-plus-57 value; the sprite callee reads its low byte.
- The sprite painter reads its source segment from `DS:C1FA`. Source zero
  uses background byte `DS:79A3`, or skips with `INC DI` if that background
  is zero. Source one uses ink byte `DS:661E`, even when the substituted ink
  is zero. Other source indices are retained. Actual stores honor DF.
- Ammunition is capped at 99 in the local byte, without changing inventory.
  The opaque two-digit destination is `(y+19)*320+x+8`, with 16-bit wrap.
  The entry preserves the original scratch writes and Pascal `RET 6` cleanup.

The production HUD previously used an unindexed dark rectangle, a transparent
sprite helper and transparent number painting. Its original-backed test failed
before the fix at case 1, destination pixel 52281: actual index zero, expected
18. The painter now uses indexed background 18, background/ink-aware sprite
painting and the existing opaque objective-number helper. Three-argument
`TextRenderer::drawSprite` calls retain transparent-background/index-one defaults.

The App now owns the recovered `DS:79A3` icon-update clobber through its existing
shared `corpseRewardRoll_` byte, and supplies sprite ink from its existing
damage-lane `DS:661E` owner. All production inventory-sampling sites use that
owner-aware wrapper. A new actual-App diagnostic checks those owners and the
production presentation sampler; it loads assets before resetting the level.

## Validation

The core test runs 26,712 replay configurations: instruction grants 1, 2, 17
and 4096 crossed with REP limits 1, 2 and 65535. It restores snapshots after
every grant, compares 11,968,936 boundaries, 30,615,144 logical dispatches and
5,776,200 transfers, plus full endpoint memory and ordered writes. Zero and
finished budgets are inert. Intermediate control flags and all endpoint flags
are compared; intermediate arithmetic flags are not. Unicorn's raw REP transfer
and zero-CX observations are explicitly mapped to the C++ grant contract, not
relabelled as original normal-core work credits.

Two additional computed timer-interrupt cases check restoration while a sprite
callee owns a different DS, both standalone and nested beneath the HUD. They
are not captured original interrupt schedules.

The production renderer matches 393,216 indexed icon/count pixels across 1,024
shipped dirty-icon cases. Another 32 original sprite cases check 4,144 pixels
covering transparent/background/ink substitution, including opaque ink zero.
The actual App checks all 2,048 cases: 1,536 admitted calls, 512 no-call controls,
shared-byte updates and ink ownership. Fourteen App-fixture corruption controls
must be rejected before asset loading.

Eight independently compiled mutants are rejected: dirty gate, count clamp,
shared scratch, Pascal cleanup, signed centering, clear stride, transparent
background and index-one ink. The unchanged compiled control passes.

The Linux App/selected-target build and 40 distinct focused CTests pass,
including the existing reserve/HUD/foreground, natural-campaign, boss-reentry,
state-2, live HUD and render-view checks. Strict native MSVC CPU replay and the
complete GCC ASan/UBSan replay pass. Native Windows Python passes seven fixture
tests; App execution and symbolic-link creation are explicitly skipped there.
Linux runs all nine, including the actual App and link controls. Native Windows
Git and Linux cold checkout preserve the five present fixture families,
including the new App binary, and demonstrate five CRLF negative controls.

## Proof Limits

This completes bounded ammunition/rectangle/sprite callees and corrects the
production HUD's corresponding painting and shared-byte ownership. It does not
complete the outer `7C3D..7EBB` waiting loop or `1B14` end-run UI, integrate these
callees into the production instruction clock, or prove natural call timing,
original IRQ scheduling, live VGA/DAC timing, a natural boss victory or whole-game
parity. The displayed original/C++ icon crops use controlled memory and the same
shipped palette; they are not natural gameplay screenshots.

All build, capture and dependency outputs remain in WSL `/dev/shm` under the
RAM-only authorization while C: exceeds its reserve threshold. Native MSVC
CPU replay is not a native Windows App build or physical-input acceptance.
