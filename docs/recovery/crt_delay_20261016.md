# Resumable original CRT delay

## Scope

`core/crt_delay.hpp` translates the 19 instruction states at original CRT
`CS+084a:029c..02c8` into a budgeted C++23 operation. The original caller at
`1000:79df` pushes the delay argument and makes the far call; return is
`1000:79e8`. This operation is not wired into `App` or its governed loop yet.

One work unit is one decoded instruction dispatch. It is not a CPU cycle,
millisecond, or natural wall-clock measurement. The operation preserves live
segmented reads and writes through a supplied bus, including calibration reads
at `DS:7f68`, byte polling at `0040:0000` (the COM1 base byte, not the BIOS timer),
near-call stack writes, and both near and far return addresses read from the
live stack. Memory ownership and physical address policy belong to the bus.

Snapshots retain the register cursor, code segment, defined-flag mask, completed
dispatch count, and return state. Restoring a snapshot does not copy or restore
the external bus. Zero budgets and completed operations do no work. Unsupported
instruction cursors or code segments fail explicitly; this is not a generic
x86 emulator or an implementation of corrupted interrupt-handler execution.

`LOOPE` decrements the 16-bit counter with wraparound and preserves flags.
`DEC` preserves carry and computes signed overflow. Logical instructions leave
AF undefined, so comparisons exclude AF until a later instruction defines it;
retaining its numeric value is not an equality claim. See the
[Intel instruction-set reference](https://cdrdv2-public.intel.com/774492/325383-sdm-vol-2abcd.pdf)
for OR, XOR, DEC, CMP, and LOOPE flag semantics.

## Controlled Original Evidence

The frozen observations come from the unchanged installed `LEZAC.EXE`:

- SHA-256: `7579255148c2cb540b26f70dc8181c50b218b6808d8fa5208c832391bafa53ec`.
- Routine SHA-256: `5b41023c828ecea8d4fc62bad88b831733dd83443d69cfc4c7f57bcb49baadd9`.
- Producer SHA-256: `2a62c875cdf7199c869c17bf7cabca41e977c298721d45e7a0d552d07f408ce4`.
- Unicorn 2.1.4, MZ relocation applied, original caller instructions executed.
- All 43,552 relocated code bytes verified unchanged after every case.
- No original calls stubbed, instruction patches, injected hardware interrupts,
  or accepted unexpected port I/O/software interrupts.

Inputs are deliberately seeded and calibration/COM1 reads are scripted. This
is controlled execution, not a read-only capture or a natural gameplay trace.
The scripts include zero and maximum words, the captured 544 calibration and
16/81/82 arguments, startup 500/1000 arguments, live calibration changes, and
COM1 changes/restoration. The maximum-argument case includes checkpoints around
the `DX=8000 -> 7fff` signed-overflow boundary.

There are 17 cases, 758 snapshots, and 13,273,201 original CRT dispatches. Each
snapshot contains selected registers, defined flags, eight live stack bytes,
and calibration/COM1 read counters. Two independent input-delivery mechanisms
produce identical complete case arrays:

1. Read hooks restricted to physical `00400` and `22988`.
2. Instruction hooks supplying data just before the original read instructions,
   with no memory-read hooks.

Both mechanisms use the same Unicorn engine. Their agreement is an observer
control, not validation against a second CPU emulator or real DOS hardware.

During exploratory capture, a global memory-read hook caused a wrong far-return
IP despite correct stack bytes. Restricted read hooks and the instruction-only
provider returned correctly. Failed probes and diagnostic controls are retained
outside the repository in RAM. This is a local observer artifact, not a claim
that all Unicorn versions or earlier repository captures are affected.

## Validation

`crt_delay_original` replays every snapshot twice: exact checkpoint budgets, and
irregular budgets including zero with reconstruction after every advance. It
also tests live altered return addresses, read failure cursor preservation,
unsupported control flow, and after-return no-ops. Thus 1,516 snapshot comparisons
cover registers, defined flags, live stack bytes, read counts, and dispatches.

Ten locally compiled negative controls are rejected: clamped zero-counter
wrap, frozen calibration, re-latched COM1, ignored poll changes, ignored ZF,
cleared carry on DEC, fixed near return, wrong far-return stack adjustment,
budget overrun, and claiming defined logical AF. The normal header is unchanged
by the mutation runner; its logs are retained in the RAM validation checkpoint.

`crt_delay_fixture_contract` uses only the Python standard library. It pins the
original executable, producer, manifests and fixture bytes; validates typed
scope/profile fields and snapshot structure; and rejects contradictory claims,
malformed snapshots, changed provenance, and provider disagreement. Regenerating
observations requires optional Unicorn; ordinary CI does not install it.

Example controlled recapture, with Unicorn supplied externally:

```sh
env SDL_AUDIODRIVER=dummy PYTHONDONTWRITEBYTECODE=1 TMPDIR=/dev/shm \
  python3 -B tools/capture_original_crt_delay.py \
  --out /dev/shm/crt-delay-new-memory --provider memory
```
