# Original HUD-To-Keyboard Frame Bridge

## Recovered Execution

`FrameHudOperation` closes the original `79E8..7A00` HUD prelude and composes it
with the recovered keyboard drain through `7A13`. It executes actual caller
branches, Pascal stack frames, runtime stack checks, palette requests, decimal
digit selection, indexed word blits and the original runtime Move. Console/
INT23 and runtime-error handling stop at explicit handoffs rather than stubs.
Production App scheduling and gameplay are unchanged by this stage.

The original number renderer writes its glyph source pointer to DS:2074, the
same physical word used earlier by elapsed-time/pacing code. The operation
preserves that alias, destination DS:2072, cached counters, completion flags,
two-slot palette capacity, duplicate-index updates and exact stack cleanup.
Digit blits write all indexed bytes, including background pixels.

## REP And Clock Composition

Normal-core REP is budget-sensitive. It reimburses the decode decrement and
charges each transfer; a short budget leaves CX nonzero and repeats the same
instruction at a later decode. `PicWorkClock::chargeStringTransfers` recovers
this rule, including the zero-count credit and one-cycle corner cases.
`FrameHudOperation` receives transfer grants from this computed clock rather
than reading later observed budgets. IRQ0 context can suspend either HUD/runtime
execution or the delegated keyboard operation.

## Natural Original Evidence

The authoritative silent r3 run enters one both-counters-updated bridge and one
unchanged bridge, with 673 and 20 states. C++ matches all 693 states twice:
1,386 register, stack, shared-memory, clock/device and indexed-pixel comparisons
across uninterrupted and per-dispatch snapshot/restore modes. The 272-pixel
HUD bands yield 376,992 indexed-pixel comparisons, not full-frame pixel parity.
Initial font and sound-bank bytes remain unchanged. Zero-budget calls do not
dispatch, charge REP or alter snapshots.

The updated window uses the existing VGA/idle/silent device clock. The unchanged
window starts with a dirty render-palette flag. A core-only replay adapter keeps
those initial device observations unchanged and rejects any foreign callback
or millisecond ticker boundary; it does not pretend to recover dirty-palette
callback effects. Neither window observes IRQ0 entry, so this corpus does not
prove natural HUD-interrupt timing or general active-device eligibility.

Five raw RAM/PNG checkpoints independently match all 43,552 relocated original
code bytes. The emulator exits zero with a terminal trace and unchanged
canonical assets. Read-only VGA pixel getters require the actual chain-four,
linear-base and bank profile. All capture, parser, contract, getter, observer,
patch, build and incremental rebuild producers are frozen-source bound.
Raw RAM/PNG files remain local; frozen checking reports `raw_ram_files_verified=0`.

The earlier r1 is retained as failed category coverage: it reached both-changed
and unchanged windows, not the initially required byte-only class. Its original
host/probe were preserved before incremental rebuild. r2 is retained as a
superseded provenance run, including its successful local clock replay. Only
fresh r3 with the explicit incremental-rebuild producer binding is frozen.

## Controlled Original Evidence

Seventeen controlled profiles execute unchanged original HUD, stack-check,
Move, palette and raster code in Unicorn 2.1.4 with zero original-call stubs or
instruction patches. A separate unobserved engine matches full endpoint
registers and all 1 MiB of memory. The compact corpus retains only owned input/
endpoint slices and the original digit atlas, not full RAM dumps.

C++ matches full endpoint flags, stack, globals, unchanged atlas and indexed
pixels in both unlimited and one-transfer copy modes. Cases cover isolated and
combined counter updates, both completions, duplicate/full palette queues,
direction flags, signed-word boundaries and the real runtime-error handoff.
These controlled endpoints do not establish natural reachability or matching
Unicorn/DOSBox REP dispatch counts.

## Acceptance Boundary

This is the recovered HUD-to-keyboard fragment, not a complete frame or App
cadence integration. Downstream player/render work after 7A13, active IRQ1 and
repeat, dirty-palette callback effects, complete screen/palette output and
natural wall-clock behavior remain unproved. No whole-game fidelity claim is
made. Full local App/full-suite validation was not rerun above the Windows
90-percent disk guard; new captures/builds/checks remain RAM-only under the
explicit user exception. Current-head review and fresh CI are required.
